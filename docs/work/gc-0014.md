## Scope

Move canonical coordination state to `var/coordination/` in the primary game-coordinator checkout, keyed by registered writer. Use Markdown for plans and prose, JSON for structured records, and an append-only file history. Coordination Kit owns the storage contract and migration. The coordinator owns user-directed holds and operational cutover.

## Criteria

- Role and worker namespaces preserve verified ownership. The coordinator owns explicitly scoped user holds. Handoff readiness remains owner-attested.
- Senders publish immutable messages by ID. Recipients record their own disposition by the same ID. Rebuildable indexes and guarded notifications reference durable originals.
- Order hold changes with covered work starts, and preserve atomic recovery for handoffs and other updates involving multiple records.
- Preserve exact records, IDs, evidence, pending questions, holds, and existing callers during migration. Compare imported and rebuilt state with existing evidence before switching authority.
- Resolve the canonical root from the explicit primary coordinator checkout for every caller, independent of working directory or worktree. Qualify the new checkout-local target without permitting live state in other checkouts or task worktrees. Keep live state ignored and commit shared configuration, schemas, policies and work specifications as applicable.
- Qualify independent backups outside the checkout, restore, compatibility and one fenced switch from the current external store. Keep delivery controls and scheduled cadence.

## Decisions

- D1 (user, 2026-11-21): Place the canonical live file store in the primary coordinator checkout under ignored `var/coordination/`. Keep backups outside the checkout and commit shared, reviewable files.
