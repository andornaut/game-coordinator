## Scope

Apply the collaboration review across Coordination Kit, Delivery Kit and the coordinator. Kit owners qualify their source and the coordinator qualifies adoption through the existing release and review procedures.

## Criteria

- Status shows open work, recorded questions and holds alongside recent activity. Unmatched imports remain visible.
- The decision owner can record an explicit answer when work-file writeback is unavailable. Pending writeback is visible and recoverable.
- Reviews provide exact original messages, identify newly stalled IDs and report native visibility and worker coverage within bounded reads.
- Delivery reports the exact captured commit. Routine successes produce one completion notice, with full event history and prompt failure notices.
- Recovery uses the registry as the authoritative identity source. Verify remaining compatibility readers before retiring duplicate writes.
- A newly resumed role receives its startup orientation once its exact frontend is observable. An ambiguous orientation reports the original ID for reconciliation before retry.
- Readiness, diagnosis and wake delivery use the same managed endpoint selection. Record wake outcomes and next safe actions alongside message dispositions. Verify representative live send, pull and handling paths. Report delays by original ID and owner at the existing review boundary.
- Before presenting a Codex question, record its owner, exact text, ordered options and dependent work in the existing ledger. Attach the native request identity when available. Reconcile the same durable question at resume and during existing reviews.
- While a question is open, keep incoming messages visible through a verified passive notification or the existing status channel. Keep independent approved work eligible. Preserve explicit role holds and block work that depends on the answer.
- Resurface the original form only through a supported client operation that preserves its pending identity. Otherwise show the exact recorded question and owning session in status. The owner may re-ask after verified closure without an answer and link the new request to the same durable question. Leave unknown native state unresolved.
- Verify with a real Codex prompt across compaction or reconnect. Incoming messages remain visible and are collected once. The original options and answer identity survive, and an explicit answer releases only dependent work. Preserve Claude behavior in this slice.

## Decisions

The user approved durable question recovery, scoped dependent-work blocking and passive inbox visibility, starting with Codex.
