## Scope

Keep bounded history for closed messages and routine coordination events. Coordination Kit owns compaction. The coordinator reviews the first live dry run and enables pruning at an existing review boundary after qualification.

## Criteria

- Start with 100 closed messages per recipient, ordered by close sequence. For routine non-message events, use the same initial count per source stream, ordered by commit sequence. Report counts and bytes per stream so the window can be tuned from observed activity.
- Consider only handled or superseded originals outside the window. Keep open, retained, disputed and unresolved messages and their dependencies. Treat missing ownership or evidence as a reason to keep the original.
- Preserve designs, decisions, approvals and material evidence in their owning records. If a message supplies the sole copy or a live reference still requires its original body, protect it until the owner records a verified durable replacement.
- Compact routine events only after a verified checkpoint preserves live work and decisions, holds, delivery evidence, current runner identity, ingest cursors and deduplication keys. Protect unconsumed or ambiguous records and any event required by an open reference. Keep runner outbox rotation on its existing cursor-checked path.
- Keep a minimal ID and disposition record for deduplication, supersession and reference resolution. Expiration must remove the payload from replayable active history, including duplicate projections. Keep independent backups under their recovery policy.
- Provide a read-only dry run with eligible and protected counts, bytes and reasons. Qualify rebuild, restore, concurrent writes, retry and interrupted compaction before operating on live data. Preserve guards, the message lifecycle and normal delivery. Use the current review cadence.
